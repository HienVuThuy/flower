--------------------------------------------------------------------------------
1.1  Một yêu cầu đi qua Laravel như thế nào
--------------------------------------------------------------------------------
  Người dùng mở https://.../gio-hang
    1. public/index.php                 cửa vào duy nhất của mọi yêu cầu
    2. bootstrap/app.php                cấu hình: nạp route, đăng ký middleware
    3. Middleware (bộ lọc chạy trước)   vd: đã đăng nhập chưa, có bị khoá không
    4. routes/web.php                   tìm dòng khớp địa chỉ + phương thức
    5. Controller                       hàm xử lý yêu cầu
    6. Service                          nơi chứa luật nghiệp vụ (tính tiền, kho…)
    7. Model                            đọc/ghi bảng trong CSDL
    8. View (Blade)                     dựng HTML
    9. Middleware (chạy sau)            vd: thêm header bảo mật
   10. Trả HTML về trình duyệt

  Ví dụ thật: bootstrap/app.php đăng ký middleware:
      $middleware->appendToGroup('web', PreventBackHistory::class);
      $middleware->append(\App\Http\Middleware\SecurityHeaders::class);

--------------------------------------------------------------------------------
1.2  Route (đường dẫn) — routes/web.php, routes/admin.php
--------------------------------------------------------------------------------
  Route::get('gio-hang', [CartController::class, 'index'])->name('shop.cart.index');
    - get / post / put / patch / delete : phương thức HTTP
    - 'gio-hang'                        : địa chỉ
    - [CartController::class, 'index']  : gọi hàm index của CartController
    - ->name('shop.cart.index')         : TÊN route; trong code dùng
                                          route('shop.cart.index') để sinh URL,
                                          đổi địa chỉ không phải sửa chỗ khác

  Route::prefix('admin')->name('admin.')->middleware(['auth', 'role:admin,staff'])
       ->group(function () { ... });
    - prefix   : mọi route bên trong bắt đầu bằng /admin
    - middleware: mọi route bên trong phải đăng nhập và là admin/nhân viên
    - group    : gom nhiều route cùng cấu hình

  Tham số trên URL:
      Route::get('san-pham/{product:slug}', ...)
    Laravel tự tìm sản phẩm có cột slug khớp rồi truyền vào hàm controller dưới
    dạng biến $product (gọi là "route model binding"). Không có thì trả 404.

  ->whereNumber('post') : tham số phải là số.
  ->middleware('throttle:10,1') : tối đa 10 lần mỗi 1 phút, quá thì báo 429.

  routes/admin.php chứa toàn bộ route quản trị, được nạp ở cuối routes/web.php
  bằng dòng  require __DIR__.'/admin.php';

  routes/console.php : lịch chạy tự động (Schedule::command(...)->dailyAt('08:00')).

--------------------------------------------------------------------------------
1.3  Middleware — app/Http/Middleware
--------------------------------------------------------------------------------
  Mỗi middleware có hàm  handle(Request $request, Closure $next).
    - Gọi $next($request) = cho yêu cầu đi tiếp.
    - Không gọi (abort(403) / redirect) = chặn lại.

  Ví dụ app/Http/Middleware/CoQuyen.php → handle():
      foreach ($ma as $m) {                         // các quyền ghi trên route
          if ($user->duoc($quyen)) return $next($request);   // có quyền → đi tiếp
      }
      abort(403, 'Tài khoản của bạn không có quyền vào khu vực này.');

  Trong route viết  ->middleware('quyen:kho')  thì $ma = ['kho'].

  Các middleware của dự án:
    EnsureUserHasRole     chặn theo vai trò (admin / staff / customer)
    CoQuyen               chặn theo khu vực quyền (don-hang, kho, tai-chinh…)
    EnsureUserIsNotLocked tài khoản bị khoá thì đăng xuất ngay
    PreventBackHistory    không cho trình duyệt lưu trang cần đăng nhập
    GhiNhanNgayGhe        ghi nhận ngày ghé thăm để tính chuỗi ngày
    SecurityHeaders       thêm header bảo mật cho mọi phản hồi

1.4  Controller — app/Http/Controllers
--------------------------------------------------------------------------------
  Controller trong dự án được giữ MỎNG: nhận dữ liệu → kiểm tra → gọi service →
  trả kết quả. Không tính tiền, không trừ kho ở controller.

  Ví dụ app/Http/Controllers/Shop/CommunityPostOwnerController.php → pin():
      $bai = $chuBai->baiCuaToi(Auth::user(), $post);   // lấy bài CỦA TÔI
      try {
          $ghim = $chuBai->doiGhim($bai);               // luật nằm ở service
      } catch (CommunityException $e) {
          return back()->with('error', $e->getMessage());   // báo lỗi đỏ
      }
      return back()->with('success', 'Đã ghim bài…');       // báo xanh

  Các cách trả kết quả hay gặp:
    return view('shop.cart.index', ['cart' => $cart]);
        → dựng resources/views/shop/cart/index.blade.php, truyền biến $cart
    return redirect()->route('shop.orders.show', $order);  → chuyển trang
    return back()->with('success', '...');  → quay lại trang trước + lời nhắn
    return response()->json([...]);         → trả JSON cho JavaScript

  Chia thư mục: Shop/ (khách), Admin/ (quản trị), Auth/ (đăng nhập),
  Api/ (JSON), Concerns/ (đoạn dùng chung giữa nhiều controller — "trait").

1.5  Kiểm tra dữ liệu gửi lên (validation)
--------------------------------------------------------------------------------
  Cách 1 — ngay trong controller:
      $data = $request->validate([
          'body' => ['required', 'string', 'max:1000'],
      ], [], ['body' => 'bình luận']);
    Sai thì Laravel TỰ quay lại trang trước kèm lỗi; đúng thì $data chỉ chứa
    các trường đã khai → an toàn khi lưu.

  Cách 2 — Form Request (app/Http/Requests), dùng khi luật dài:
      public function rules(): array    // luật
      public function messages(): array // câu báo lỗi tiếng Việt
    Controller chỉ cần khai kiểu:  public function store(AddressRequest $request)

  Luật hay gặp: required, nullable, string, integer, email, max:255, min:1,
  confirmed (có ô nhập lại), image, mimes:jpg,png, exists:bảng,cột,
  Rule::enum(OrderStatus::class) (giá trị phải thuộc enum).

--------------------------------------------------------------------------------
1.6  Service và "tiêm phụ thuộc" (Dependency Injection)
--------------------------------------------------------------------------------
  Service = lớp PHP thường chứa luật nghiệp vụ, nằm ở app/Services/<Miền>/.

  Laravel tự tạo đối tượng và truyền vào, gọi là tiêm phụ thuộc:
      class OrderService
      {
          public function __construct(
              private readonly CouponService $coupons,   // Laravel tự tạo
              private readonly OrderMailer $mailer,
          ) {}
      }
    "private readonly CouponService $coupons" trong ngoặc của __construct là cú
    pháp rút gọn (constructor promotion): vừa khai thuộc tính, vừa gán giá trị.
    readonly = gán một lần, không sửa được nữa.

  Cũng có thể xin service ở bất kỳ đâu:  app(PricingService::class)->resolve($p)

  Singleton (chỉ tạo một lần cho cả yêu cầu) khai ở
  app/Providers/AppServiceProvider.php → register().

--------------------------------------------------------------------------------
1.7  Model Eloquent — app/Models
--------------------------------------------------------------------------------
  Mỗi model ứng với một bảng: Product ↔ products, OrderItem ↔ order_items.

  Đọc:
      Product::find(5)                          tìm theo id, không có → null
      Product::findOrFail(5)                    không có → 404
      Product::where('status', 'active')->get() danh sách (Collection)
      Order::where('user_id', Auth::id())->latest()->paginate(10)
  Ghi:
      Order::create([...])           tạo mới — chỉ nhận cột trong $fillable
      $order->update([...])          sửa
      $post->forceFill([...])->save() sửa cả cột không nằm trong $fillable
                                      (chỉ dùng với dữ liệu do máy chủ tự đặt)
      $product->decrement('stock_quantity', 2)   trừ 2

  $fillable / $guarded : danh sách cột được phép gán hàng loạt. Chống việc kẻ
  xấu gửi thêm trường "role=admin" lên biểu mẫu.

  $casts / casts() : đổi kiểu khi đọc, vd 'approved_at' => 'datetime',
  'status' => OrderStatus::class (đọc ra thành enum).

  Quan hệ:
      public function items(): HasMany       { return $this->hasMany(OrderItem::class); }
      public function user(): BelongsTo      { return $this->belongsTo(User::class); }
    Dùng:  $order->items  (danh sách),  $order->user->name

  Scope — điều kiện đặt tên sẵn:
      public function scopeApproved(Builder $query): Builder
      { return $query->whereNotNull('approved_at')->whereNull('hidden_at'); }
    Dùng:  CommunityPost::approved()->get()   (bỏ chữ "scope", viết thường)

  Nạp sẵn quan hệ (eager loading) — chống lỗi N+1:
      Product::with(['category', 'promotions'])->get();
    Không có with(): 20 sản phẩm → 1 truy vấn lấy sản phẩm + 20 truy vấn lấy
    danh mục = 21 truy vấn (lỗi N+1). Có with(): 2 truy vấn.
      ->withCount('reviews')  thêm cột reviews_count
      ->withAvg('reviews', 'rating')  thêm cột trung bình

  Xoá mềm (SoftDeletes): xoá chỉ ghi deleted_at, dữ liệu vẫn còn, khôi phục
  được (sản phẩm, đơn hàng).

1.8  Migration — database/migrations
--------------------------------------------------------------------------------
  Tệp mô tả cấu trúc bảng; chạy  php artisan migrate  để áp vào CSDL.
      Schema::create('wishlists', function (Blueprint $table) {
          $table->id();
          $table->foreignId('user_id')->constrained()->cascadeOnDelete();
          $table->foreignId('product_id')->constrained()->cascadeOnDelete();
          $table->timestamps();
          $table->unique(['user_id', 'product_id']);    // không trùng cặp
      });
    - up()   : áp thay đổi.  down() : hoàn tác.
    - constrained() : khoá ngoại tới bảng users / products.
    - cascadeOnDelete() : xoá người dùng thì dòng yêu thích bị xoá theo.
  Tên tệp có ngày giờ ở đầu để chạy đúng thứ tự.
  database/seeders : tạo dữ liệu mẫu (php artisan db:seed).
  database/factories : tạo dữ liệu giả trong kiểm thử (User::factory()->create()).

1.9  Enum — app/Enums
--------------------------------------------------------------------------------
  Danh sách giá trị đóng, thay cho chuỗi gõ tay dễ sai.
      enum OrderStatus: string
      {
          case Pending = 'pending';
          case Completed = 'completed';
          public function label(): string { return match ($this) { ... }; }
      }
    OrderStatus::Pending            một giá trị
    OrderStatus::from('pending')    từ chuỗi → enum (sai thì lỗi)
    OrderStatus::tryFrom('abc')     sai thì trả null
    OrderStatus::cases()            mọi giá trị
  Dự án dùng enum cả để chứa luật nhỏ, vd OrderStatus::canTransitionTo()
  quyết định đơn được chuyển sang trạng thái nào.

1.11 Tính tiền bằng bcmath — KHÔNG dùng số thực
--------------------------------------------------------------------------------
  Máy tính lưu số thực gần đúng: 0.1 + 0.2 = 0.30000000000000004. Với tiền, sai
  một đồng cũng là sai, nên dự án tính tiền trên CHUỖI số:
      bcadd('100.50', '20', 2)   = "120.50"   cộng, 2 chữ số thập phân
      bcsub(a, b, 2)             trừ
      bcmul(a, b, 2)             nhân
      bcdiv(a, b, 2)             chia
      bccomp(a, b, 2)            so sánh: -1 (a<b), 0 (bằng), 1 (a>b)
  Ví dụ app/Services/Pricing/PricingService.php → applyDiscount():
      giảm %:  bcsub($base, bcdiv(bcmul($base, $value, 4), '100', 2), 2)
             = giá gốc − (giá gốc × % ÷ 100)
  Hiển thị tiền: app/Services/Shop/Money.php → format().

1.12 Giao dịch CSDL và khoá dòng
--------------------------------------------------------------------------------
  DB::transaction(function () { ... });
    Mọi lệnh ghi bên trong thành công hết, hoặc lỗi thì HUỶ HẾT. Đặt hàng mà trừ
    kho xong rồi lỗi ghi đơn → kho được trả lại như cũ.

  Product::whereKey($id)->lockForUpdate()->first();
    Khoá dòng đó tới hết transaction. Hai người mua món cuối cùng cùng lúc:
    người thứ hai phải chờ, tới lượt thì kho đã về 0 → báo hết hàng.

  UPDATE có điều kiện (app/Services/Coupon/CouponService.php → redeem()):
      Coupon::whereKey($id)
          ->where(fn ($q) => $q->whereNull('usage_limit')
                               ->orWhereColumn('used_count', '<', 'usage_limit'))
          ->update(['used_count' => DB::raw('used_count + 1')]);
    Kiểm và ghi trong MỘT câu lệnh → hai người không cùng lấy được lượt cuối.

  Idempotency (chống làm hai lần): app/Services/Checkout/CheckoutGuard.php sinh
  một khoá ngẫu nhiên lưu trong session; cột orders.idempotency_key là duy nhất
  nên bấm "Đặt hàng" hai lần vẫn chỉ ra một đơn.

1.13 Collection — danh sách có sẵn nhiều hàm
--------------------------------------------------------------------------------
  collect([1,2,3]) hoặc kết quả ->get() của Eloquent.
    ->map(fn ($x) => $x * 2)       biến đổi từng phần tử
    ->filter(fn ($x) => $x > 1)    giữ phần tử thoả điều kiện
    ->sum('quantity')              tổng
    ->pluck('name')                lấy một cột
    ->groupBy('category_id')       gom nhóm
    ->sortByDesc('score')          sắp xếp giảm dần
    ->first(), ->isEmpty(), ->count(), ->take(4), ->values()
    ->reduce(fn ($carry, $x) => ..., $khoiDau)   gộp dồn thành một giá trị

  "fn ($x) => ..." là hàm mũi tên (arrow function) viết gọn.

1.14 Exception nghiệp vụ — lỗi có câu nói sẵn cho khách

  RefundException, InstallmentException, CommunityException…
  (nằm cùng thư mục với service tương ứng).

1.16 JavaScript của dự án — resources/js
--------------------------------------------------------------------------------
  - resources/js/app.js là cửa vào: import các tệp nhỏ và gọi hàm init… khi
    trang tải. Mỗi tệp một việc (add-to-cart.js, cart-live.js…).
  - "export function initX()" ở tệp con, "import { initX } from './x'" ở app.js.
  - Uỷ quyền sự kiện: document.addEventListener('submit', ...) rồi kiểm
    event.target.closest('form.product-buy') — nhờ vậy nút thêm vào trang sau
    vẫn chạy.
  - fetch + FormData (resources/js/ajax.js → guiForm()): gửi biểu mẫu không tải
    lại trang, kèm header Accept: application/json để máy chủ trả JSON.
  - NGUYÊN TẮC "nâng cấp dần" (progressive enhancement): mọi nút đều là biểu mẫu
    thật chạy được khi tắt JavaScript; JavaScript chỉ làm cho mượt hơn. Có lỗi
    thì .catch(() => form.submit()) gửi theo cách thường.
  - Dữ liệu gán vào trang bằng textContent (không phải innerHTML) khi đó là chữ
    người dùng nhập → chống XSS.
  - Đóng gói: npm run build (Vite) → public/build. Blade nạp bằng @vite(...).

PHẦN 5. BẢNG TRA NHANH THUẬT NGỮ
================================================================================

  MVC                 Model (dữ liệu) – View (giao diện) – Controller (điều phối)
  Service layer       lớp chứa luật nghiệp vụ, tách khỏi controller
  Route               quy tắc nối địa chỉ web với hàm xử lý
  Middleware          bộ lọc chạy trước/sau controller
  Eloquent / ORM      thao tác bảng CSDL bằng đối tượng PHP
  Migration           tệp mô tả thay đổi cấu trúc bảng
  Seeder / Factory    tạo dữ liệu mẫu / dữ liệu giả cho kiểm thử
  Eager loading       nạp sẵn quan hệ bằng with() để tránh N+1
  N+1                 lỗi hiệu năng: 1 truy vấn danh sách + N truy vấn từng dòng
  Transaction         nhóm lệnh ghi "được cả hoặc không gì cả"
  lockForUpdate       khoá dòng để hai người không cùng sửa
  Idempotency         làm nhiều lần cho cùng một kết quả
  CSRF                giả mạo yêu cầu từ trang khác; chặn bằng @csrf
  XSS                 chèn mã độc vào trang; chặn bằng {{ }} và làm sạch HTML
  SQL Injection       chèn lệnh SQL; chặn bằng truy vấn có tham số
  Mass assignment     gán hàng loạt cột; chặn bằng $fillable
  Rate limit/throttle giới hạn số lần gọi trong một khoảng thời gian
  HMAC                chữ ký bằng khoá bí mật để chứng minh dữ liệu không bị sửa
  IPN                 thông báo thanh toán máy chủ MoMo gọi thẳng về
  OTP                 mã dùng một lần
  Hash / băm          biến đổi một chiều, không đảo ngược được (lưu mật khẩu, OTP)
  Enum                danh sách giá trị cố định
  DI (tiêm phụ thuộc) Laravel tự tạo và truyền đối tượng vào hàm khởi tạo
  Singleton           chỉ một đối tượng dùng chung
  Observer            lớp tự chạy khi model được lưu / xoá
  Scope               điều kiện truy vấn đặt tên sẵn trong model
  Component (Blade)   mẩu giao diện dùng lại <x-...>
  Progressive enhancement   chạy được không cần JS, có JS thì mượt hơn
  Levenshtein         số lần sửa ký tự tối thiểu để biến từ này thành từ kia
  Trung vị (median)   giá trị đứng giữa dãy đã sắp xếp
  UTC                 giờ chuẩn quốc tế, giờ Việt Nam = UTC + 7
  Polling             trình duyệt hỏi máy chủ định kỳ (vài giây/lần) để lấy dữ
                      liệu mới — cách livechat của dự án cập nhật tin nhắn
  Livechat            nhắn tin trực tiếp giữa khách và nhân viên
  bcmath              thư viện tính số chính xác trên chuỗi
